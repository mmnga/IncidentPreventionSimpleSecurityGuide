# Codex用バックログ — 実装優先順位・受け入れ条件

各タスクは独立したPRに分離し、既存220 IDと `REVIEW PASSED / STATIC ONLY` の意味を維持する。初回はP0を優先し、P1/P2は計画を提示して着手範囲を確認してもよい。

2026-10-13に、skillの正本を `skills/repository-security-audit/`、開発用テストを `tests/` へ整理しました。当時のbaseline検証を含む旧資料は、事例資料の分離に伴い `private-case-studies/originals/validation/` へ移動しています。以下は継続開発のバックログであり、配置整理で配布物生成まで実装したことを意味しません。

## P0 — 誤判定防止と配布保守（最優先）

### P0-1 基準状態の再現と契約テスト
- **変更**: 引き継ぎ資料にあるテスト・CLIの実行確認。既存の未検証事項を明示したテスト記録を新規作成。
- **完了**: 全テスト合格（現在275件、基準197件）、static初期結果が`INCOMPLETE`/exit2、220/172/48、scope_id・evidence gate、HTMLオフラインが維持されること。
- **禁止**: 実プロダクトのコード実行、証拠なしでのPASS、検出ルール数とカバー率の混同。

### P0-2 単一正本＋配布物生成
- **現状**: 正本は `skills/repository-security-audit/` に集約済み。旧配布資料にあったホスト別コピーは現在のcheckoutには含まれず、配布物の生成スクリプトは未実装。
- **変更**: この正本からCodex/Claude/Cursor向け自己完結パッケージを **決定的・再実行可能** に生成するスクリプト、hash一覧、差分チェックを設ける。
- **完了**: 生成後に4配布物のコード/台帳のバイト一致が確認できる。1つの新ルール追加が全配布物に再現でき、完全に同じコマンドでビルドできる。
- **注意**: コピー差分で `scope_id` が変わる設計。既存レビュー証拠の不正流用を許さない。移行が必要なら明示的な手順を作る。

### P0-3 判定と証拠の不変条件のテスト
- **変更**: 子条件FAIL/欠落が親PASSで隠れない、旧scope/異なるsnapshotの証拠拒否、gap未補完拒否、WAIVED拒否、`OUT_OF_SCOPE`改ざん拒否、空ファイル・完全無検出でも自動合格しないことのテストを整理。
- **完了**: `REVIEW PASSED`には明確な証拠が必要で、staticではfull_auditが未評価。exit0以外の扱いをCIで誤解しない。

## P1 — 実用性と検査精度

### P1-1 字句検出から構造レビューを補助する設計へ
- **背景**: 現行75ルールは単純な正規表現が中心。63チェックに候補を付けるだけで172項目全部を自動判定しない。
- **変更案**: 対応言語を選定し、信頼済み環境で構文解析・データフローの根拠抽出や外部SAST/SCAの*結果取込*を検討。外部ツールは許可済みdigestとschemaで固定し、安全なオフライン入力に限定。
- **完了**: 各ルールの真陽性・偽陽性fixture、検出位置、理由、対象言語、制限、レビュー待ちが明示される。未サポート言語はgapとする。
- **禁止**: 対象コードの実行や自動インストール。候補を自動FAIL/PASSにする近道。

### P1-2 HTML Resultの改善
- **変更案**: 重大度別の優先度、ファイル/行、関連チェック、判定根拠、確認候補と確定指摘の区分、差分比較の設計。既存検索・フィルタ・IPA/ARTEXテーマを残す。
- **完了**: ローカルファイルで完結（外部通信なし）、文字列escape済み、モバイル対応、`OUT_OF_SCOPE`・未実施状態を見失わない。重大度がない指摘には推測ランクを付けない。

### P1-3 Git履歴/SCA/依存とcoverageの整合
- **変更案**: 提供済みの静的履歴、SBOM、SCAスキャン結果を安全に取込む証拠adapter。対象repoのGit hook/依存実行はしない。
- **完了**: 範囲未取得はBLOCKED/NOT_RUN。供給物とsnapshotの結合、hash照合、バージョンが説明可能。

## P2 — 後続要件が確定したら着手

### P2-1 サブエージェントの並列・項目別レビュー（基本手順は実装済み）
- **現状**: 2026-10-16に既定手順と `review_workflow.py plan/merge` を実装。親がホストの2以上のworkerを起動し、全172 IDを配分・照合する。v9.2の現行は184個別条件。CLIはagentを起動しない。
- **検証済み**: 担当の欠落/重複、条件未提出、未起動/失敗、証拠の不整合、根拠なし非該当の拒否。未起動時も172 IDを個別の未確認として保持。実ホスト2workerの限定合成4 IDレビューも実施し、全件監査とは区別した。
- **後続案**: 正式なホスト機能向けadapterと実行記録の取込。JSONのagent自己申告だけで実行・本人性・並列性を証明したと扱わない。利用不可なら並列未実施を明記する。

### P2-2 リリース・監査品質
- **変更案**: CIで複数Python版、チェック台帳の一意性、UIスナップショット、パッケージ差分、署名・provenance運用。
- **完了**: 再現可能なZIP、署名がない場合は「署名なし」、最新版調査・防御条件の出典区別、継続メンテナンス手順。

## 対応しない範囲

ユーザーの現行要件により、DAST、実際のペネトレーションテスト、リモート/本番環境へのスキャン、ランサムウェア実行、実データの転送/削除、資格情報検証は対象外。

## 実装時の報告テンプレート

変更IDと対象ファイル / 検証動機 / 既存チェックへのマッピング（重複の有無） / 合格条件の変更点 / 追加したfixturesとテスト結果 / セキュリティ上の限界 / 利用者が判断すべき点。
