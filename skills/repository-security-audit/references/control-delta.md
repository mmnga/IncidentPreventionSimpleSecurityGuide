# v5：重複を増やさない対策チェック差分

**220項目を維持 / 新規ID 0 / 既存54項目を強化（ランサム40、その他14）**。
54項目の中に個別の合格条件108件を設けた。これは220件に加算する新規チェックではない。各条件に検証方法・必要証拠・状態を持たせ、単一の親PASSで省略できないようにした。

## 反映方針
対象・リスク・合否検証の意味で照合する。完全カバーはそのまま再利用、一部不足は既存IDを強化、本当に未カバーの場合のみ新IDを発行する。事例名、年月、攻撃グループ名の違いだけでは新IDを作らない。

## 追加しなかった対策

| 対策 | 再利用先 | 判断 |
|---|---|---|
| 公開bundle・モバイルアプリにサーバーsecretを含めない | SEC-05, REL-01 | 配布物内のsecretと公開設定を検査する既存の合格条件でカバー。 |
| .env・バックアップ・DB dumpの意図しない公開を防ぐ | SEC-03, REL-03 | ファイル存在だけでなく配布経路と公開対象の検証が既にある。 |
| 他人・別テナントのデータをAPIで取得できない | AZ-01, AZ-02 | オブジェクト/テナント単位の否定試験が既にある。 |
| API tokenを必要なscopeと有効期限へ限定する | SEC-07 | 実効scopeと期限を検証する既存項目へ対応付けのみ。 |
| 事故時にtoken・鍵を実際に失効する | SEC-10, IR-02 | 通常の失効試験SEC-10を維持し、横断失効不足のみIR-02で強化。 |
| 共通原因の複数事例を同じ是正チケットに結び付ける | IR-10 | 事例数・年度・攻撃グループ名を理由に新しい検査IDを増やさない。 |

## 根拠と検証手順の区別

資料は対策設計の根拠であり、全てのテスト手順が事故報告に直接記載されているわけではない。安全な否定試験、証拠の分割、判定期限は本スキルで具体化した設計である。国内1年の全事故に対する網羅率・件数を主張しない。

## 互換性

証拠schemaは2、エンジンは5.0.0。v4の証拠を直接再使用しない。変更済み台帳・エンジンで新たにscope IDを取得し、追加条件を検証する。更新前の定義はcontrol-delta.jsonのbeforeに保存されている。
