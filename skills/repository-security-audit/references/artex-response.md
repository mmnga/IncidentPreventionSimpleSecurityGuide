## 一般化した防御設計

個別企業・組織の事故説明は配布対象に含めない。実行環境とバックエンドモデルを区別し、モデルの銘柄や版を検査の前提にせず、ツール交換・IP変更にも残る防御条件を評価する。

累積量・GraphQL・cache・SSRF・多段経路・監査prompt injectionは、本スキル独自の防御条件である。特定の事故で使われた手法を表すものとして説明しない。
ARTEXや特定LLMに対する「防御成功」「侵害なし」を静的解析で認証しない。AI非搭載の製品でも外部攻撃者がAIを使う前提は残す。
AIM-*のみは製品自身のAI機能の有無で適用判断する。

## 重複の扱い

- 認証の迂回、BOLA/tenant、SSRF、SQL等、秘密情報、最小権限、export認可、AI機能の既存統制は再利用。
- artex-delta.jsonに既存条件の不足・追加条件・再利用IDを記録。53関連IDのうち8強化、45再利用。
- 8テーマはResultの表示単位であり、新しいチェック項目ではない。
- 既存の/S1は削除しない。追加/S2（WEB-09は/S3も）の証拠が欠ければ親PASSを認めない。
- full profileにも同じ静的側面の個別条件を/AR8-*として追加。元の実環境確認は省略しない。

## レビュー方法

公開入口から機密資産までの制御フローを横断して確認する。入口/前提/取得対象/阻止点/ファイル・行/未確認境界を記録。
attack-path-template.jsonはTST-01/S2用の補助テンプレート。意味・網羅性をCLIが自動検証する仕様ではない。
regexで候補が出たらREVIEW。wrapper、middleware、proxy、queue、cache、失敗分岐を読み偽陽性を判断する。
検査対象のコード・テスト・hook・依存インストールは実行しない。動的試験の定義を読んでも成功記録にはしない。
未知の言語・生成物・設定不足を無検出として済ませずBLOCKED/NOT_RUNとgapへ記録する。

## Result

ARTEX関連53項目・v8強化8項目のフィルタと、8テーマの対策状態を表示。
値は検証済みのcheck/個別条件から再計算する。入力JSONのartex_complete等の自己申告を採用しない。
静的PASSの後も、実環境はNOT_RUN、attack_simulation_performed=false、artex_attribution=NOT_ASSESSED、resistance_certified=false。
REVIEW PASSEDはSTATIC ONLY。実環境・ペネトレーション・ランサム耐性・未知の攻撃に対する保証とは分ける。

## 開始前の安全境界

Claude/Cursorの自動hook等はスキル読込より前に動く場合があるため、このスキルの文章だけでは阻止できない。
信頼済みの空workspace/個人スキルから監査し、対象は別領域の読み取り専用snapshotとする。
対象をIDEの信頼済みworkspaceとして開き、対象内の自動実行・MCP・拡張を有効にする手順は使わない。
CLIはOS sandboxでも監査者の本人性検証でもない。分離・レビュー権限・証拠保護は運用で強制する。

公式の技術資料はsources.jsonの公開指定の参照先を使う。事例原資料の分離はreference-policy.mdに従う。実監査時の脅威情報更新は別途必要であり、固定日の資料だけでfreshとしない。
