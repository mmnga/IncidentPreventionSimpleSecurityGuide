# 事例資料と配布用資料の分離

配布するskill・レポート・開発文書には、企業・組織を特定できる被害事例、引用、事例記事の題名・URLを記載しない。説明は「何を確認するか」「必要な証拠」「修正する場所」「未確認の範囲」へ一般化する。架空例と公式の一般的な技術資料・指針は利用できる。

開発時の事例原資料は、repo直下の `private-case-studies/` に保存する。このディレクトリはGit管理対象外であり、skill本体の外に置く。監査CLIからの自動読込、レポートへの埋込、Webサーバーの配信先、配布物への同梱は行わない。事例を含む過去資料は内容を変えず同フォルダへ移し、原パスとhashをローカルのmanifestへ記録する。

`sources.json` の `visibility: "public"` だけがHTML掲載対象。`visibility: "private"` は互換性のための参照ID、対応チェックID、従来の確認日だけを保持し、企業名・題名・URL・本文は持たない。公開指定のない資料もHTMLへ出力しない。非公開資料に代わる出典を捏造したり、原資料を今回確認したように確認日を書き換えたりしない。

参照IDや個別条件IDは証拠の照合用であり、事例紹介の表示名として使わない。原資料の追加だけでチェックを増やさず、既存の条件へ対応付け、不足する防御条件だけを追加する。資料の分離によって、判定条件・証拠の期限・scope/hash・状態・終了コードを緩和しない。
